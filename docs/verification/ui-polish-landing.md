- `pnpm typecheck`, `pnpm lint`: clean.
- `pnpm check:brand`: passed. `node --test scripts/check-branding.test.mjs`: 24 of 24. A first version of the new hook was rejected by lint and the brand check (a selector string matched the arbitrary-value pattern); it was rewritten, not exempted.
- `pnpm test` (vitest): 24 files, 291 tests passed.
- `pnpm build` and `pnpm check:chunks`: passed; entry chunk 115.2 kB gzip against a 150 kB budget; preview and AI SDK exclusions held.
- `playwright test` (standard config, built with `pnpm build:e2e`, Moto S3 fixture, fake identity provider, memory-storage API): **74 of 74 passed**, including the landing spec: axe WCAG 2 A/AA/2.1 AA, 200% text, reduced motion, no horizontal overflow, the DNA's `animation-name: none` and transform, mascot natural width, role-aware actions.
- The landing preview screenshots in `docs/design/previews/` were regenerated by that run.

## Found and fixed during verification

The first build revealed blocks by fading from opacity 0. axe then reported `color-contrast` on every unrevealed block below the fold. That is a real regression (any static audit would see it), so entrances became transform-only with no opacity change. Re-run after the change: the landing spec and the whole standard suite passed.

- Database and S3 tiers of the backend suite were not run; there is no backend change.
