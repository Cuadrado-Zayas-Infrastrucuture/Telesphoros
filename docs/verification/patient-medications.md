## Implementation

Migration 0066 adds one immutable, ledgered row per medication entry version, FORCE RLS, checked vocabularies and real year-month ordering. The clinical API accepts only coded drug identifiers from the bundled list and takes the canonical name from that list. It never accepts a caller-supplied drug name. A correction includes its entry id and expected current version; competing corrections cannot silently overwrite each other. Request ids are required, scoped by tenant and actor, and replay the original version even after later corrections. Retry fingerprints stay out of responses and ledger projections.

`GET /api/v1/patients/:id/medications` lists current entries, active first. `?entryId=<uuid>&version=N` selects an entry's historical version. Clinicians write; readers, reviewers and clinicians read. Administrators and roleless members get 403. An inaccessible patient gets 404. In-memory persistence returns 503.

The ledger's shared projection registry necessarily learns the medication record; clinical engines and the verifier do not import the medication module or repository. The verifier can check the record digest without interpreting any medication. The existing eligibility function recognizes the `medication` fact kind, identifies a mismatched patient/fact, and always returns ineligible with `medication-release-held`. Origin provenance for analytic use remains unestablished, and E3/D07 are unchanged.

FDA Tall Man names are display-only. `drugPresentation` returns visual and plain accessible names; `matchesDrug` ignores case. Existing product screens are unchanged; MD-b must apply the shared presentation helper when it adds the medication picker and list.
