# One poisoned outbox event no longer halts the relay (2026-10-23)

Date: 2026-10-23

**Implemented (migration 0036, labelled `breaking`).** From the production-readiness audit (item 44, High). `outbox_relay` ran its whole loop in one block with no error handling: a failure while making the job for one event (a constraint or trigger on `jobs` refusing it) raised out of the function and rolled back the batch, and the next call picked the same earliest event again, for ever, so no organization's events became jobs. Now each event is handled in its own sub-block; a failing event's changes are undone, a `WARNING` names it (id and SQLSTATE only) and the loop goes on. The event is not marked and not given a new outcome, so it stays pending: a transient failure is retried on the next call, and nothing is lost. Timeouts and cancellations are not caught, so a statement that runs too long still ends the call. One function body replaced; the down file restores the 0024 body.

**Tests, written first.** In `apps/worker/test/outbox.pg.test.ts`: with a trigger refusing one organization's jobs, the earliest event is poisoned and two healthy events behind it. On the old function the relay raised `synthetic poison` (red); now the healthy events are relayed, the poisoned one stays pending with no job, the call returns instead of raising, and once the cause is removed the next relay makes its job. A variant that swallows the error and marks the event relayed fails the test. The existing atomicity test ("when the job cannot be made...") encoded the old behaviour by expecting the relay to raise; it now expects the call to return 0 and keeps its other assertions (event pending, no job, then exactly one job on the next relay).

**Made visible in the same change.** A failing event is quiet (the call returns, so the worker logs no failure and `worker-relay-failing` stays silent). Migration 0036 therefore also adds `outbox_stats()` (pending events and the age of the oldest, cross-tenant like `job_stats()`, granted to the worker's role only; `provision-logins` now checks that grant); the worker puts `outboxPending` and `outboxAgeSeconds` on its `queue-stats` line, and a new alarm, `worker-outbox-stuck`, fires when the oldest has waited more than ten minutes. Terraform written, never applied. The contract test runs the worker's own log line through the filter; the guard pins the metric, threshold and silence handling with three new weakened-text controls and one worker-side control.

**Risk and limits.** `CREATE OR REPLACE FUNCTION` is `breaking` under the migration lint; nothing is deployed, so no outage window is spent. A failing event is retried on every call and, if as many sit at the head as the batch size, still crowds the rest out (the alarm would fire). The poison in the test is a synthetic trigger; no real event is known to fail. The ten-minute threshold is a judgement (normal lag is seconds), not a measurement.

**Not established.** Nothing observed in AWS.
