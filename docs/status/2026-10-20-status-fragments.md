# Status entries are fragments in docs/status/ (local, 2026-10-20)

Date: 2026-10-20

`docs/STATUS.md` had 115 sections with each new entry inserted at the same spot near the top, so it conflicted in 14 of the last 19 merges; the repository needs an up-to-date branch before merge, so every conflict cost a hosted CI rerun (about $0.37; limit 3 per pull request). New entries are now one file per pull request, `docs/status/YYYY-MM-DD-slug.md`, with a `# Title` line and a `Date:` line that matches the file name. `pnpm status:index` (`scripts/status-index.mjs`) prints the index newest first; it is not committed, because a committed index would be a second shared file. A guard in `pnpm test:ci-config` (`.github/ci/status-fragments.test.mjs`) checks the heading, a real date that matches the file name, a unique slug, and that nothing but fragments sits in the folder; each rule has a control that breaks it on purpose. The 115 existing sections and their anchors are untouched; `docs/STATUS.md` gains one short pointer section, and CONTRIBUTING, the spec-driven workflow, the agent context and implement-slice skill, and the pull request template now ask for a fragment. Not touched: migrations and their hard-coded lists, product code, Terraform, workflows, `CLAUDE.md`. This entry is the first fragment.
