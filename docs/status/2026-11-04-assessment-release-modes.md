# Release modes for the synthetic assessment (032 S3, PR 3c-3a)

Date: 2026-11-04

The staging release recipe can now switch the synthetic assessment on and off. It could not before: the canonical var file `current.tfvars` is hashed and refuses hand edits, and an IMAGE plan may differ from it by exactly the two image lines, so `synthetic_assessment_enabled` (PR 3c-2) had nowhere to go. Two new modes, `ASSESSMENT-ON` and `ASSESSMENT-OFF`, change that one variable and nothing else, keep the running image, replace the API task definition and move its service in place, and add or remove exactly the two settings Terraform writes. Nothing has been planned or applied against staging.

What changed: the one-flag engine of the medication fence (`fence-vars.mjs`, `fence-plan.mjs`, `plan-record.mjs`, `release-check.mjs`, `plan.sh`, `apply.sh`, `apply-run.sh`, `lib.sh`) now serves four modes instead of two, with the medication behaviour and wording unchanged; the new modes keep their evidence under `releases/COMMIT/assessments/OPERATION_ID/`. `ASSESSMENT-ON` waits for this commit's IMAGE apply, complete migrations and a signature record for the running image, and checks them again at apply; `ASSESSMENT-OFF` waits for nothing. [synthetic-assessment-switch.md](../ops/synthetic-assessment-switch.md) has the commands and what the checks prove; `staging-release.md` and the plan table point to it.

Verification, Node 22.22.0: `assessment-plan.test.mjs` 79 of 79 (new), `fence-vars.test.mjs` 8 of 8 (was 4), `release-scripts.test.mjs` 7 of 7 (was 6, the new one runs the real `plan.sh` and `apply.sh` against stubs), `api-compute.guard.test.mjs` 7 of 7 (it now compares the checker's expected settings with `api-compute.tf`); the unchanged medication tests still pass (`fence-plan` 41, `release-check` 33); `test:infra` 388 of 388 and `test:ci-config` 221 of 221. Nineteen deliberate breaks of the new code each failed the test meant to catch them (one first survived, because the secret check only does unique work when the same secret is on both sides of a plan; that case is now tested) and every file was restored byte-identical.

Not done: no plan, apply or release against staging, so none of this is proved on a real Terraform plan; the offline tests use invented plan JSON and stubbed Terraform. `ASSESSMENT-ON` refuses an unsigned break-glass image, as `FENCE-OPEN` does, which the founder may relax for synthetic staging. The founder-run release and the live walkthrough (PR 3c-3) are next.
