# The API has a client for the session issuer (DATA-01 PR B, local)

Date: 2026-10-21

Nothing called the issuer: the API still used `NullCapabilityIssuer`. `apps/backend/src/issuer/issuer-http-client.ts` now implements the port over node's `fetch` against `POST /v1/capabilities` (`{accessToken, requestId}` in, `{token, expiresAt, membershipVersion}` out, as slice 3 PR A changed it), selected by a new `ISSUER_URL` setting (absolute `http(s)`, no credentials, query, fragment or path; an unusable value stops the API at start-up without repeating it). Unset, nothing changes. The call has one 2500 ms deadline (provisional, under the guard's 3000 ms wait; D4's real budget needs the staging measurement), at most one retry and only for a network failure or a 503, a 4 KiB cap on the answer, a strict parse, no redirects, and every unclean answer is `unavailable` with a closed code. Status plus the `error` field map to the port's closed reasons, so the two 403s stay apart. No token, body or address is logged, and the phrase the issuer's alarms count is not written by the API. A static test pins that the client loads the port and nothing else of the issuer; a real-issuer test calls the live server through the client.

`api-compute.tf` joins the internal Service Connect namespace as a client-only member and passes `ISSUER_URL`, built from `issuer.tf`'s own name and port, both only while `enable_issuer` is on (default false), so the default plan is unchanged. T017 is ticked (it was built in slice 2), T018 is ticked with its limits, and the transport plan has a fourth addendum.

Local only: nothing is pushed, nothing applied in AWS. Not verified: the API container's resolution of `session-issuer` and the proxy's behaviour (503 while no task is healthy, `Connection: close`), and the latency. Decided with the founder: an unset `ISSUER_URL` stays the null issuer, with no `ISSUER_REQUIRED` setting; slice 5 (T031) decides what production does when enforcement is on and it is unset. Details: `docs/design/plans/tenant-capability-issuer-transport.md`, addendum 4.
