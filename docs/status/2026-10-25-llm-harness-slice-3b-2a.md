# LLM harness slice 3b-2a: the durable run store and asynchronous ports

Date: 2026-10-25

**Implemented.** Migration `0049_agentic_explain_runs` (labelled `breaking` for the same lint reason as 0048; every object is new). `agentic_explain_runs` holds the idempotency key as a hash, the request as a keyed digest, the fenced state, sequence, fence and deadline, no text. Four capability-bound functions for the application login (`_admit`, `_get`, `_advance`, `_cancel`) see only the caller's own organization and requester; a suspended organization is refused. The state machine is in SQL (31 legal moves, one list) and in a row trigger; `advance` is a compare-and-swap under a row lock (of eight concurrent advances exactly one wins); `cancel` raises the fence. A run its process never finished is expired by the next admission of its key and by an operator sweep; a finished run is frozen; deletes are refused until 2190 days (the founder's 6-year rule, extended to runs); an organization may admit at most 1000 runs an hour. `apps/ai-service/durable/run-store.ts` implements the run's `ExplainStore` port against it. The run's `ExplainStore` and `ExplainBudgets` ports are now asynchronous, and `runExplanation` awaits them; a store that rejects ends the run held with the engine text. The request digest that the run keeps for idempotency is now keyed (HMAC) instead of a plain SHA-256.

**Controls.** 30 PostgreSQL specs for the table (isolation, hostile parameters, twenty concurrent admissions, eight concurrent advances, the 121-pair transition truth table against an independent statement of the rule, freeze and ordering as a non-superuser owner and as a superuser, `ENABLE ALWAYS` under `session_replication_role = replica`, retention, sweep and purge, shape, privileges, down migration); a test in the default run that reads the migrations and compares the SQL state list, the 31 pairs, the run deadline and the receipt reason codes with the TypeScript; 19 unit tests of the adapter; four local-only tests of `runExplanation` against the real store (release, replay, conflict, a concurrent pair, a cancel during work, an orphan). Ten mutations broken on purpose, each red (see `docs/verification/llm-harness-slice-3b-2a.md`).

**Not changed:** the receipts table, the synthetic agentic tables and functions, `kernel.ts`, the engine, Terraform, the AWS account. Pins updated for the new table: schema-acceptance, the table classification, the 0031 revert test's removed-function pattern, the durable-surface allowlist, `provision-logins` rights (with four negative controls), one down-guard case, and the receipts spec's down test (a migration now sits above 0048).

**Not done (slice 3b-2b):** the usage reservation and the fleet and tenant caps under concurrency (T025, T027), which need the founder's cap numbers. Nothing in a running service uses the run store yet, and the budgets are still the in-memory test double. Nothing schedules the operator sweep and purge.
