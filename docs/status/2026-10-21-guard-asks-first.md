# The guard asks for the capability before it reads the membership (DATA-01 slice 3 PR A, local)

Date: 2026-10-21

`AuthGuard` used to read the caller's membership first, because the issuer needed the membership version, so that one lookup could never carry a capability and was left out of the D7 count. Migration `0030_tenant_capability_issue_current` (`expand`) adds `tenant_capability_issue_current` (issuer login only: it reads the current active membership version itself and issues through the existing function) and `app_capability_version()` (the version a presented capability was issued at; the roles that already bind through `app_tenant()`; not PUBLIC). `CapabilityIssueRequest.membershipVersion` is gone, `IssuedCapability` and the issuer's HTTP answer carry the version, the guard obtains the capability first and looks the person up under it, and the `duringAdmission` / `isAdmitting` exemption is deleted, so every `withTenant` call is counted. The request's authority is held to the version the capability carries: a membership that moves between the issuance and the lookup refuses writes at commit.

Refusals follow decision D1=(i): when the issuer refused the person (`membership-not-current`, `tenant-inactive`) its `capability_issuance_log` row is the record and the API no longer writes `access.refused` for `no-membership`, `removed` or `tenant-suspended`. With no issuer configured (today's default) or one that failed, the API still writes them, because nothing else would. `token-revoked` and `authority-changed` are unchanged. `migration-lint` now also accepts handing back a schema `CREATE` the earlier migrations had already taken from an existing role (0030 needs it for `telesphoros_capability`, as 0028 did for its new role).

Binding mode stays `guc`; no policy, definer function, mode row, Terraform or workflow is touched. Local only: nothing is pushed, nothing applied in AWS. Details, the injected-defect table and the local loop: `docs/verification/tenant-capability.md`, "Slice 3 PR A".
