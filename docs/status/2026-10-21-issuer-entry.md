# The session issuer has a process entry (DATA-01 PR A, local)

Date: 2026-10-21

The issuer core had no listener, so the ECS task in `issuer.tf` had nothing to run. `apps/backend/src/issuer/main.ts` is now that entry: plain `node:http`, not a Nest application, compiled by the existing backend build to `dist/issuer/main.js` and shipped in the existing image (no new bundle, no Dockerfile change). `POST /v1/capabilities` takes `{accessToken, membershipVersion, requestId}` (JSON only, 8 KiB cap, exactly those keys) and answers `200 {token, expiresAt}` or a closed status: 401 invalid token, 403 no tenant, 400 invalid request, 403 refused (with the database's closed code only), 503 unavailable. `GET /livez` is the health check; everything else is 404. `IssuerCore`'s `Capability not issued: <reason>` lines still reach stdout unchanged for the two metric filters, and no token, claim, database message or address is written. Its own environment loader refuses to start in production on any missing value, on the Cognito development overrides, on `DATABASE_SSL` other than `require`, and when the application's own secrets are present. A test pins the exact list of files the entry may load, so the API's pool, its configuration and the worker cannot be reached by accident; ten mutants turn it red.

`issuer.tf` now runs `command = ["dist/issuer/main.js"]`, without a leading `node`: the image's `ENTRYPOINT` is `node` and an ECS command only replaces `CMD`, so `["node", ...]` runs `node node ...` (checked with `docker run` on an image built from the Dockerfile). The worker task and the migrate and provision-logins tasks are written with a leading `node` and are not changed here; that is a follow-up. The old guard tripwire (the Dockerfile contains the text `issuer/main.js`) is replaced by one derived from `tsconfig.build.json` and the Dockerfile. `enable_issuer` still defaults to false, because the API has no client yet.

Local only: nothing is pushed, nothing applied in AWS. Not verified: the Service Connect proxy's bind-address behaviour (the entry binds `0.0.0.0`), the x86 Fargate image and ECS itself. Details and the full list: `docs/design/plans/tenant-capability-issuer-transport.md`, addendum 2.
