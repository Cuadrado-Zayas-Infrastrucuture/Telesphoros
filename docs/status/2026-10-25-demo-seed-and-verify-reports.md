# Local demos: seeded users and verify scripts that name the failing step

Date: 2026-10-25

`pnpm demo:review:setup` and the `pnpm demo:storage` runtime now register the demo organizations and grants every fake user their membership, derived from the groups in `packages/fake-idp` (a user with exactly one `tenant:<id>` group and at least one role). Since the live-membership slice the API reads each person's standing from the database, and the setup seeded none, so on a fresh checkout every demo user was refused (403) and `verify-review` and `verify-operations` failed at their first call; the scripts had drifted because nothing ran them. The seed is safe to run twice. The four `verify-*` scripts now report through one helper that prints the script and line and, for a failed assertion, the two short values compared, never an object, header or token.

Verified: on a new cluster the setup seeded 6 members of 2 organizations and `verify-upload`, `verify-review` and `verify-operations` passed with no manual step; a second setup changed nothing; five defects (no seed call, a wrong derivation, a seed that grants nothing, a report that prints any value, a script with its own report) each turned `pnpm test:demo-seed` red. The seeding test needs PostgreSQL, so it is skipped (and says so) in the CI `verify` job, which has none; the derivation, the setup wiring and the failure report run there. The public repository's review demo needs the report-reader engine's captures, which it does not carry, so only `demo:storage` runs end to end there; with the seed, a user signs in to the storage demo and sees Reports and Upload report instead of "No organization is assigned to your account" (checked in a browser). No backend, migration, Terraform or AWS change.
