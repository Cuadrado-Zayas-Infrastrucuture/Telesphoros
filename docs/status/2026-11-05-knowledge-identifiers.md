# Knowledge identifiers, schema 1.3 (spec 033, slice 1)

Date: 2026-11-05

A knowledge file can now carry standard identifiers and say where its content came from. Schema 1.3 adds an RxCUI to each guideline, an HGNC id, an origin and (where the map lists alleles) a PharmVar release to each gene map, and an origin (`cpic`, `pharmgkb`, `pharmvar` or `unknown`) to each guideline cell. Schema 1.2 files still parse to exactly what they did, so no content hash or knowledge set id changes. A synthetic file must use the invented `syn-` forms and a real file the real forms; a reviewed, non-synthetic file may not state origin `unknown`, and production refuses a reviewed, non-synthetic 1.2 file. The engine copies the identifiers of the chosen cell onto each result that has a citation, only when the guideline and every gene map are 1.3; they change no outcome, reason code, hold or wording. Migration 0071 (`compat: breaking`: new checks on an existing table) stores them on `evaluation_results` with all-or-none and format checks, and the hashed projection includes them only when present, so every earlier result hashes as it did. The down file refuses while any row carries identifiers.

What changed: `packages/cpic-schema` (`knowledge.ts`, `evaluation.ts`, tests); the knowledge loader; the recommendation engine; migration 0071 up and down; the ledger records repository and `projections.ts`; `data/fixtures/knowledge/synthetic-identifiers/` (a new invented 1.3 set; the two existing sets are untouched); `test/helpers/knowledge.ts` and `test/helpers/schema-acceptance.ts` (the six new constraint names); `docs/cpic-integration.md`; `docs/clinical-validation/knowledge-identifiers.md`; the spec, plan and tasks in `specs/033-knowledge-identifiers/`.
