# Twenty UX details evaluated for Telesphoros

Date: 2026-11-01. Scope: public Telesphoros web app. The original evaluation began on main `4449161e` while PatientPicker PR #235 was open. Delivery rebased this UX-only branch onto main `50b2f180`, retaining the merged shared PatientPicker, its accessible instructions and PR #236 list ordering. The patient-creation lock and retry behavior were integrated with that picker; both sets of regression tests remain. Synthetic data only. No backend, dependency, infrastructure or clinical-content change.

## Decisions and how to see them

Paths below are relative to the repository root. Built means a suitable frontend addition was implemented; it does not claim every literal platform-specific example in the supplied list applies.

| # | Detail | Verdict | Evidence, changes and how to see it |
| --- | --- | --- | --- |
| 1 | Skeleton loaders | Built | `src/styles/tokens.css` now delays shared skeletons 300ms. `UsageSummary.tsx` renders both loaded values and decorative placeholders through the same cards/rows; `UsageReportView.tsx` uses that layout. Open Usage as an administrator and throttle/hold its request. Reports already shares its fixed table frame. This is not a guarantee that every variable-length response has zero layout shift. |
| 2 | Optimistic updates | Skipped | No harmless server-backed likes/renames exist. Patient creation, demographics, report storage and review wait for authoritative API responses. Local checkboxes, theme and sidebar preference already respond immediately and need no `useOptimistic` layer. See `theme/ThemeProvider.tsx`, `layout/WorkspaceSidebar.tsx` and `workspace/WorkspaceConversation.tsx`. |
| 3 | Command menu | Skipped | Daily expert use is not established for this prototype. A global page/action catalog would duplicate the small role-aware navigation in `layout/WorkspaceSidebar.tsx`. Revisit with an observed daily keyboard workflow. |
| 4 | Shortcut hints | Skipped | There is no global application shortcut registry or command menu to expose. Existing native Escape/Tab in `ui/ContextDrawer.tsx` and Enter/Shift+Enter in `prompt-kit/PromptInputTextarea.tsx` remain; no new global listener can fire while typing. This does not claim a shortcut-hint system already exists. |
| 5 | Undo toasts | Built | `workspace/WorkspaceConversation.tsx`: remove an unsent attachment, then use the local status notice's Undo. The File stays in memory for eight seconds; hover or keyboard focus pauses expiry, and leaving gives another eight seconds. Undo preserves the patient and question draft. A replacement attachment supersedes it. No API request, soft delete or clinical rollback is involved. |
| 6 | Stale-while-revalidate | Skipped | Patient/report state and tenant-session boundaries should remain explicit. No shared API cache or focus/online background refetch was added. Existing request cancellation, refresh/retry and change events remain in Reports and workspace lists. |
| 7 | Prerendering | Skipped | `app/routes.tsx` uses lazy client routes; links do not configure prefetch. The public landing mainly links to sections on itself; protected routes depend on in-memory authentication and sign-in/callback flows. Speculative document loading adds little useful work for this app. |
| 8 | BlurHash placeholders | Skipped | The intake is reports, not an uploaded-image gallery. Supporting image hashes would add ingestion metadata/backend work; bundled artwork already has dimensions. The design also restricts blur to approved scroll edges. |
| 9 | View transitions | Skipped | No shared-element navigation needs animation. Stable forms, explicit list/detail context and focus restoration serve this workflow; route animation would add decoration. |
| 10 | Swipe-to-dismiss sheets | Skipped | `ui/ContextDrawer.tsx` is a side drawer containing scrollable report/evidence content, not a bottom sheet. Explicit close, Escape and focus return are already implemented. No gesture library added. |
| 11 | Interruptible springs | Skipped | No draggable or spring-animated control needs this mechanism. Buttons already use ordinary interruptible color transitions; dialogs open/close without an animation blocking input. Decorative/loading keyframes are not an interaction model to replace. |
| 12 | Predictive back | Skipped | This is a React web app, not an Android native app. Native Android back-handler APIs do not apply. |
| 13 | Hit slop/touch targets | Already done | `ui/Button.tsx`, `ui/Input.tsx`, `ui/NativeSelect.tsx` and the control tokens use the existing 44px web baseline; browser foundation tests measure controls. Native iOS/Android hitSlop APIs and 48dp platform sizing do not apply to this web implementation. Dense read-only calendar data marks are not new tap buttons. |
| 14 | Safe-area insets | Built | `index.html` opts into viewport coverage. `styles/tokens.css`, `index.css`, `workspace.css`, `one-screen.css` and `interpretation-preview.css` keep app content, sticky navigation/composer, skip link and dialogs within device insets. `layout/AppLayout.tsx`, `SkipLink.tsx` and the chat dock use them. Inspect a cutout device in portrait/landscape, or run `e2e/safe-area.spec.ts`, which overrides all four real CSS env insets in Chromium. |
| 15 | One-time-code autofill | Skipped | `pages/SignInPage.tsx` delegates authentication to the identity provider. The app owns neither an SMS-code form nor the SMS message format. Provider/backend configuration is outside this frontend slice. OAuth callback codes are not SMS one-time-code inputs. |
| 16 | Tabular numbers | Built | Added the existing `tabular-nums` utility to `usage/UsageSummary.tsx`, `UsageCalendarYear.tsx` and `ReportStages.tsx`. Visit Usage's counts/calendar or Reports' stage counters. Report table cells, pagination and file-size/date details already used tabular digits. |
| 17 | Balanced headlines | Built | `styles/index.css` balances h1–h3. `ui/CardDescription.tsx` and the Usage/Reports introductions use pretty wrapping. Inspect a narrow viewport or a long card description. Fonts, tokens, copy and preformatted/source text are unchanged; unsupported browsers retain ordinary wrapping. Landing section headings already had balancing. |
| 18 | Continuous corners | Skipped | Existing approved radius tokens consistently define card/control geometry. Squircles add decoration without improving this workflow; no corner-shape override or rebrand was introduced. |
| 19 | Idempotency and pending actions | Built | Existing patient, demographics and report creation use UUID `requestId` values in the supported JSON API contract, with backend replay handling. They were not renamed to a Stripe-style header. Chat now locks the entire send while creating its patient, uses the shared pending Button and preserves retryable creation errors separately from invalid-file errors. Hold the new-patient POST, attempt a second send, lose the successful response, then retry: the browser test verifies the same body and returned patient ID, and one upload entry. See `workspace/WorkspaceConversation.tsx`, `hooks/useAddPatient.ts`, `lib/api.ts`, `lib/ownedStorageApi.ts`. |
| 20 | Safe triangle | Skipped | No nested hover submenu exists. Navigation uses links/buttons and disclosures; the preview's question picker is click-controlled. A hover-intent library has no current use case. |

Component paths in the table are under `apps/frontend/src/components/` unless prefixed by `src/`, `styles/`, `pages/`, `theme/`, `hooks/`, `lib/` or `app/`; these are under `apps/frontend/src/`. `index.html` is under `apps/frontend/`.

## Verification and limits

Each addition is implemented sequentially. Before the next functional addition, run root typecheck, lint, workspace tests, build, infrastructure guards, CI-configuration guards, chunk/foundation checks, demo seed, workflow checks and production knowledge verification. Preserve each command's complete output and exit status under `/private/tmp/ux-<item>-*`. Affected checks run again after corrections. Browser coverage uses the real synthetic identity/API/Moto stack, and controlled response loss; page tests retain synthetic API doubles.

- Item 1: expected timing regression failed on old code; 10 focused browser cases passed, including reduced motion and shared loading/loaded card geometry.
- Item 14: expected old-code inset failures; four focused device-inset cases passed. Corrected the test's close-button name to the existing 'Back to reports'. A later root run exposed a skeleton inventory test racing the independent calendar response; it now asserts exactly the eight summary rows/placeholders.
- Item 16: four old-code browser cases failed on proportional digits; all 10 Usage browser cases then passed.
- Item 17: both old-code heading-wrap cases failed; 32 Usage/foundation browser cases then passed.
- Item 19: old-code page regression failed; all affected page cases passed. Two browser cases verified pending controls, reduced motion, same request body and same API patient ID after losing a real successful response. Corrected a test locator to use the rendered upload's accessible label.
- Item 5: old-code missing-Undo regression failed; page coverage includes restoring context, expiry and superseding input. All project checks and both focused Undo browser cases passed. The initial browser boundary test was corrected to freeze time before starting the timer. Final aggregate browser results are recorded in the shared working notes and local evidence receipt.

Delivery screenshot review after the PatientPicker integration found that the taller attached-file form could cover part of the mobile heading. The expanded form now flows with the page; the empty composer remains docked. A geometry assertion failed at 375px before repair and verifies the heading ends above the form, alongside the same pending/replay checks.

Delivery checks on main `50b2f180`: all ten project commands passed after the integration/layout repair; frontend 643 tests in 58 files. The complete browser run passed 219 + 46 + 2 cases, with five skips, before the final expanded-form layout correction. All 52 workspace/safe-area cases then passed after that correction, with two expected skips, preserving the original retry/Undo assertions and adding heading geometry. Launcher/CORS passed five cases. New synthetic screenshots were inspected at mobile/desktop sizes.

Separate PostgreSQL/S3 backend and worker service tiers, absent report-reader engine specs, FHIR IG and container-image checks are not part of these local UI runs. Skips are not passes. Device insets are Chromium emulation; real Safari/iPhone/Android hardware acceptance remains unverified. Browser screenshots contain only synthetic fixtures and are local evidence, not production screenshots. Publication is recorded in the pull request; no deployment is included. Original per-addition logs remain historical evidence, and delivery checks rerun on the rebased candidate.

## Platform references

Safe-area implementation follows [WebKit's viewport/inset guidance](https://webkit.org/blog/7929/designing-websites-for-iphone-x/) and is tested with [Chromium's safe-area override](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setSafeAreaInsetsOverride). Wrapping uses native CSS progressive enhancement, as described in [Chrome's typography guide](https://developer.chrome.com/docs/modern-web-guidance/guides/visual-design/improve-text-layout-and-legibility). Router prefetch defaults were checked against the [React Router Link API](https://reactrouter.com/api/components/Link).
