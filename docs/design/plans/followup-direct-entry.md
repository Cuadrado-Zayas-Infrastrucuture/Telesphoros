# Open the matching follow-up from a reminder
Date: 2026-11-02

Continue the founder's approved physician-convenience direction. The reminder currently links only to the patient's Follow-up section, whose first page can omit the selected thread. Add an explicit Open follow-up action from each reminder. Keep the patient/medication link for ordinary record navigation. Use the existing patient route with a validated `followup` thread UUID and the existing tenant-scoped history API; no new page, schema or write endpoint.

The patient record resolves the thread independently of the patient-list page, loads the current server version once, and opens the compact document form for clinicians only when a reminder is still open. Show patient/treatment context and current due date. Reviewers see a read-only current entry and history. Closed reminders show their current entry without automatically starting a new assessment. Invalid, unavailable or mismatched thread links show a safe error and a return-to-follow-ups action; failed reads can be retried. A navigation link never saves, completes, reschedules or dismisses anything.

Cancel/save removes only the `followup` query parameter with history replacement, keeping the patient route and section anchor; successful save refreshes the normal patient list. Opening another patient/thread cannot reuse the previous draft. Preserve the chat draft when returning to chat. Keep exactly one follow-up form mounted and keyboard focus at the selected entry/form.
