# Feature Specification: A sidebar laid out like a chat app (SRC)

**Feature Branch**: `feat/sidebar-recents`

**Created**: 2026-11-05

**Status**: Approved 2026-11-05. The founder asked for the sidebar to be organized like Claude's, chose D2 option A ("own /patients page"), directed D7-D11 from screenshots, and approved the result ("Good, finish it").

**Input**: The sidebar (specs/018, grown by specs/024 D2) stacked the brand, a "Workspace" label, New chat, Follow-ups, a Past reports list, a Patients block (a demographics line, Add patient and a list), All reports, Usage and Settings, then the account. It was long, scrolled, and mixed navigation with lists.

## Decisions

- **D1, the order (replaces the order of specs/024 D2):** top to bottom: the brand with the collapse control; **New chat** as the main action; a short block of destinations: **Patients**, **Reports**, **Follow-ups**, **Usage**, each for the same roles as before (the local preview's Workspace and Chat preview come first, in development builds only); one **Recents** list; and the **account**, pinned at the bottom.
- **D2, patients get their own page (founder, option A):** `/patients`, for clinical read roles, holds what the panel held: the patient labels (newest first, each a link to its page, "Incomplete" as a word in color), the find box past five patients, More patients, the demographics line (spec 025 T304) and, for writer roles, **Add patient**. It uses the same requests as before; no API changes.
- **D3, Recents:** the former Past reports: the first page of reports, newest first, one line each: the file name, cut short with the full name as a tooltip, and the status as a word in color from `ReportStatusText` (so the unfinished-upload wording lands here unchanged). It takes the height left between the destinations and the account and scrolls by itself. A row opens that report's details on the Reports page; the row hands over the report it already read, so nothing is fetched again and nothing goes in the address.
- **D4, the account:** one row at the bottom (the role's initial, the role, "Synthetic environment") opens a menu with "Signed in as …", the synthetic-environment notice, **Settings** and **Sign out**. It closes on Escape (focus returns to the row) and on a click outside. This replaces specs/018 D3/D6's always-visible Sign out: it is now two clicks, in the same place.
- **D5, collapse and phones:** unchanged behavior (specs/018 D3, D4). Collapsed to icons, Recents is hidden and every other entry keeps its name for assistive technology and as a tooltip; the collapse control moves next to the brand. On phones the menu button opens the same content, with Recents bounded to 40% of the screen height.
- **D7, cleaner (founder, "Make it cleaner", 2026-11-05):** the sidebar shows the wordmark alone (the byline stays on the public pages and the sign-in header); the default width is 17rem (was 15rem); Recents rows show the file name without its `.json`/`.pdf` extension (the full name is the row's tooltip), in muted text that darkens on hover, with a spoken pause before the status word.
- **D8, drag to resize (founder, "Yes, add drag-resize", 2026-11-05):** on desktop the sidebar's right edge drags its width between 14rem and 24rem, in 0.5rem steps. The edge is a slider ("Sidebar width") for assistive technology: the arrow keys move it, Home and End go to the bounds, and a double click restores 17rem. The width is an optional preference (`telesphoros.sidebar-width`, behind the same storage consent as the collapse choice); a stored value that is missing, unreadable or out of bounds reads as 17rem. There is no handle while collapsed or on phones.
- **D9, quick settings in the account menu (founder, 2026-11-05, "a small section like this ... so users can select faster", after Claude's account menu):** the menu opens with the signed-in email (from the sign-in, in memory only; the role when there is none), then **Settings**, **Theme** (match this device, light, dark: one click, the same preference as Settings > Appearance), **Cookie settings** (the storage choice), the synthetic-environment notice and **Sign out**. The account row shows the preferred name when one is set. Left out on purpose: Language (the signed-in app is English only; only the public landing has Spanish), help and feedback (nothing behind them yet), and a keyboard shortcut for Settings (Chrome uses ⌘, for its own settings).
- **D10, the account menu, organized (founder, 2026-11-05: "iterate, make it cleaner, organized and easier to use", then "include get help, languages, settings, send feedback, report bugs, view changelog and a learn more section for policies, terms of service"):** the menu is in groups: who is signed in (the name, or the role, with the email below); **Settings**, **Language**, **Get help**, **Send feedback**, **Report a bug**; **Theme** (Auto, Light, Dark, with words); **View changelog** and **Learn more**; **Sign out**. Language and Learn more open a short list in place (no flyout, so a phone works the same). Language shows English as current and says Spanish is not yet available: the signed-in app is English only. Help, feedback, bug reports and the changelog lead to the public repository's `SUPPORT.md`, its two issue forms and `CHANGELOG.md`; Learn more holds the Security policy, Code of conduct, License and Cookie settings. Every outside link opens in a new tab and says so. There is no privacy policy or terms of service yet, so none is linked. Opening the menu moves focus to its first item; ↑ and ↓ move between items, ← and → change the theme. The synthetic-environment notice moved out of the menu: the account row always shows it. This replaces D9's layout.
- **D11, compact (founder, 2026-11-05: "make it more compact, it takes too much space"):** closed, the menu is seven rows: who is signed in, **Settings**, **Language**, **Help** (Get help, Send feedback, Report a bug), **Theme** (on one line: Auto, Light, Dark, as words), **Learn more** (View changelog, Security policy, Code of conduct, License, Cookie settings), **Sign out**. Under a mouse or trackpad (`pointer: fine`) rows are 36px (`--size-control-compact`); on touch every row and theme choice keeps the 44px target the UI rules require. The menu is 15rem wide. This replaces D10's layout; D10's destinations and keyboard behavior stand.
- **D6, nothing disappears:** every former destination has a place: New chat (top), Follow-ups (destinations), Past reports (Recents), Patients list, demographics line and Add patient (`/patients`), All reports (Reports), Usage (destinations), Settings and Sign out (account menu). The "Workspace" group label is dropped.

## Out of scope

Backend APIs; the one-screen preview's `WorkspaceBar` (`/local-workspace`); the unfinished-uploads wording and controls (`fix/unfinished-uploads` owns `ReportStatusText`, `PastReports` and `WorkspaceConversation`).
